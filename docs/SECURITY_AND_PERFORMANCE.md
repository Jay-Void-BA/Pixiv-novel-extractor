# 登录安全与提取性能

## Android 安全保存登录

默认只在内存保留会话。右上角菜单开启「在此设备安全保存登录」后，当前或下一次登录的 `PHPSESSID` 会加密保存。Shiori 不存储 Pixiv 账号密码，不将会话上传至第三方服务。其他平台暂不持久保存登录信息。

- AES-256-GCM：256 位密钥、每次写入新生成的 96 位随机 nonce、128 位认证标签；应用标识和格式版本作为 AAD，检测密文篡改。
- 密钥在 Android Keystore 内生成且不可导出；硬件保护能力取决于设备。密钥不写进 Dart、配置文件、Git、日志或 GitHub Secrets。实现遵循 [Android Keystore](https://developer.android.com/privacy-and-security/keystore) 与 [KeyGenParameterSpec 的 AES-GCM 用法](https://developer.android.com/reference/android/security/keystore/KeyGenParameterSpec)。
- 密文以 `0600` 权限原子写入应用私有 `noBackupFilesDir`，应用关闭系统备份。不使用共享存储、剪贴板、浏览器 localStorage 或明文回退。
- 会话与保存时间、过期时间一并经过认证加密；本地最长保留 30 天，Pixiv 可能提前使 Cookie 失效。启动时不会访问网络，第一次读取作品时验证服务端有效性。
- 关闭安全保存只清理磁盘密文和设备密钥，当前会话继续留在内存。退出登录同时清理保存的会话、密钥、正文缓存及待保存导出文件。401 / 明确要求重新登录时先删除旧会话，再发起登录。
- 密文损坏、格式版本未知、设备密钥丢失、时间回拨或过期时拒绝恢复，并删除保存内容。系统安全存储失败会显示提示，不改用明文。

自动恢复意味着能使用此设备应用的人可能使用已保存的会话，建议设置设备锁屏。这里没有单独的密码或生物识别解锁；已导出的文件、外部浏览器与设备密码管理器由用户管理。内存中的 Cookie 仍供网络请求使用，不承诺对已被控制的系统提供保护。

AES-CTR 单独使用不提供密文完整性验证，因此本实现选用 GCM。CRT 通常指公开证书，不是保存 Cookie 的加密格式。会话 AES 密钥和签名 APK 的发布私钥是两个不同用途的密钥；本功能无需新配 Secrets，也不更换已经正式发布的签名证书。

## 请求性能

v1.0.0 逐章串行请求，并在章节间固定等待 700ms，缓存命中也会等待。v1.1.0 使用同一个客户端连接池和全局请求队列：

- 最多同时处理 3 个请求，网络请求启动间隔至少 350ms；元信息、目录、预览和重试共用限流，不随章节数创建无限并发。
- 系列元信息与完整目录并行读取；同一小说的同时读取合并成一个请求，某个读取者取消不影响其他读取者。
- 内存 LRU 缓存上限 128 篇、400 万个 UTF-16 代码单元（正文和简介），有效期 10 分钟。缓存命中无需网络和人为等待，账号变更立即清空。
- 429 / 5xx / 超时触发共享冷却，最多尝试 3 次；支持 Retry-After 秒数和 HTTP 日期。超过一分钟的冷却直接提示稍后重试，不截短服务端要求后继续猛试。
- 每个网络请求超时 25 秒，取消能终止等待并中止支持取消的 HTTP 传输。失败会取消同一批次的其他读取，结果按目录位置组装，任何失败都不生成部分文件。
- 会话切换会使旧请求失效，旧正文不能重新填充缓存；Web 本地服务保留固定上游、TLS 验证和来源校验，并转发经过校验的 Retry-After。

真实速度仍取决于网络、Pixiv 响应和 PDF 排版耗时，限流不会绕过访问权限或验证码。

## 验证

```sh
flutter test --coverage
dart run tool/benchmark_client.dart
python3 -m unittest discover -s test -p 'test_*.py' -v
# Android 模拟器 / 设备已连接，且已运行 flutter pub get：
cd android
./gradlew connectedDebugAndroidTest
```

性能基准模拟 12 章、每请求 300ms 的响应，将旧版串行 + 700ms 间隔与新版默认队列实际计时，并验证目录顺序、并发上限和重复提取的零网络请求。输出 `build/benchmark-client.json`，这是合成数据，不代表真实 Pixiv 网络测速。

开发验证 [Actions 42375988485](https://github.com/Jay-Void-BA/Pixiv-novel-extractor/actions/runs/42375988485) 的结果：旧循环 11,356ms，新队列 4,162ms（约 2.73 倍）；再次提取 571µs，新增网络请求为 0。该场景的响应耗时低于全局请求间隔，因此峰值网络并发为 1；另有乱序响应测试确认可达到且不超过 3 个并发，并保持章节顺序。

自动化还覆盖并发上限、请求间隔、请求合并与独立取消、缓存淘汰/过期、失败停止、共享冷却、退出后的旧响应丢弃和安全存储失败。Android 仪器测试实际调用 Keystore，检查 256 位不可导出密钥、重启恢复、新 nonce、篡改拒绝、丢失密钥、过期/未知格式和退出删除。测试仅使用自编会话值，不读取用户账号。

发布仍要求全部平台通过；Android Keystore 测试新增为 Release 必需条件。正式 APK 必须通过发布证书指纹、非调试构建和 APK v2 签名验证，保持原有签名门禁。
